# GitHub App: доступ и организации

## Когда это помогает?

Подключение репозитория выглядит как одно нажатие, но отвечает\
сразу на два вопроса, которые легко перепутать:

* **Может ли Nextdocs читать этот репозиторий?** — решается на\
  стороне GitHub, когда кто-то устанавливает приложение.

* **Вправе ли эта организация иметь его копию?** — решается в\
  Nextdocs, отдельно для каждой организации.

Считать ответ на первый вопрос ответом на второй — и есть та\
ошибка, которую стоит назвать вслух: установка даёт права\
приложению, а не всем, кто этим приложением пользуется.

## Что означает установка приложения

GitHub App ставится **на аккаунт GitHub** — личный или\
организации — и покрывает репозитории, выбранные при установке.\
Только чтение содержимого и событий; ни коммитов, ни\
pull request'ов.

Два следствия, о которые спотыкаются:

* **Один аккаунт — одна установка.** Повторный проход по\
  установке для того же аккаунта не создаёт вторую — он\
  перенастраивает существующую. Отдельной установки «под команду»\
  для одного и того же аккаунта не бывает.

* **Установка — не права в Nextdocs.** Она говорит, что\
  приложение может читать эти репозитории. Какие организации\
  Nextdocs вправе этим воспользоваться — решение отдельное, и\
  каждая организация принимает его сама, пройдя установку из\
  своего пространства.

Поэтому если две команды работают в разных организациях Nextdocs\
с одной и той же организацией на GitHub, каждая подключает\
приложение из своего пространства. На стороне GitHub они\
указывают на одну и ту же установку — просто каждая подтвердила,\
что распоряжается этим аккаунтом.

## Одна организация — одна копия

Репозиторий GitHub можно подключить сразу в нескольких\
организациях Nextdocs. Каждое подключение — **отдельная копия**,\
и разделение полное:

| Что | Общее? |
|---|---|
| Клон на диске | Нет — свой у каждой организации |
| Индекс кода и граф | Нет |
| README, сохранённый в Nextdocs | Нет |
| Имя репозитория в Nextdocs | Нет — переименование меняет вашу копию |
| Список доступа | Нет |
| Удаление | Нет — только вашей копии |

Подключить тот же репозиторий второй раз **внутри одной**\
**организации** не даёт ничего нового: вы получите тот же\
репозиторий, а не его дубль.

Общее у копий — источник. Пуш в основную ветку обновляет каждую\
подключённую копию: каждая подтягивает изменения,\
переиндексируется и обновляет свои страницы — по своим правилам\
доступа.

### Почему не одна общая копия

Общий клон означал бы, что удаление в одной организации уносит\
данные другой, переименование в одной всплывает на карте сервисов\
другой и — что важнее всего — приватный код лежит в хранилище,\
которое обслуживает запросы людей, которым его никто не давал.\
Копии стоят места на диске; общий доступ стоит изоляции.

## Если доступ пропал

Удаление приложения с аккаунта GitHub или исключение репозитория\
из выбранного списка прекращает доступ Nextdocs на чтение.

* Уже сгенерированные страницы остаются. Они ваши: это\
  документация, а не зеркало кода.

* Обновления прекращаются: ни подтягивания изменений, ни\
  переиндексации, ни регенерации по пушу.

* Страница репозитория сообщает об этом, а не молча перестаёт\
  работать.

Повторная установка восстанавливает связь, и следующий пуш\
продолжит с того же места.

## Частые вопросы

**«Подключил репозиторий, а получил другой, со старым id —\
почему?»** Потому что он уже был в этой организации. Внутри одной\
организации подключение идемпотентно.

**«Мы две разные компании на одной общей организации GitHub».**\
Каждая подключает из своей организации Nextdocs. У каждой своя\
копия, свой список доступа и своя документация; правок друг друга\
они не видят.

**«Подключение репозитория раздаёт код всей команде?»** Оно даёт\
вашей организации копию по правилам доступа вашей организации —\
тем же, что управляют проектами и страницами (см. *Права доступа\
и приглашения*).

**«Репозиторий приватный, приложение не установлено».** Значит,\
подключить его нельзя. Публичные репозитории работают без\
установки, приватные — нет, и знание URL этого не меняет.
